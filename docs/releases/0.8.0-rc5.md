## Release changes

This maintenance candidate corrects optional-feature diagnostic claims, Android
credential sensitivity and API33+ task-preview suppression; strengthens verified
lock-only dependency refresh and operational-limit/status guidance; and retains
bounded Windows cleanup diagnostics without changing resource ownership or limits.
It adds actual authenticated-v2 PING/PONG measurement; the controlled loopback
comparison showed no consistent TCP_NODELAY speedup. See the
[changelog](../../CHANGELOG.md#080-rc5--development-release-candidate-2026-10-20).
The earlier productive Windows provider and Android accepted-socket repairs remain.
Library bytecode stays JVM 17; the Windows native sample retains its pinned JDK 21
runtime. Android source builds retain API24 and NDK `29.0.14206865`.

## Limitations and immutable history

- [API24–32 task-preview privacy](https://github.com/p2pKit/P2pKit/issues/479)
  remains unresolved: these versions do not receive the API33+ suppression.
  No universal leak or legacy reproduction is claimed.
  Separate [API35 acceptance](https://github.com/p2pKit/P2pKit/actions/runs/39420260605)
  and [API37 permission/recreation/TCP acceptance](https://github.com/p2pKit/P2pKit/actions/runs/39427390346)
  cover their recorded hosted scopes, not every OS or the installed published packages.
- [Discovery availability risk #120](https://github.com/p2pKit/P2pKit/issues/120)
  remains High and unaccepted. Existing caps and identity checks do not establish
  flood fairness or resolve denial of service.
- Historical rc3 Windows RPC Host/Client remains unavailable. Later provider
  repairs do not complete installed qualification: the Back deadline failure,
  zero fully accepted automated UI cycles and partial W01–W11 remain. The earlier
  successful manual report is bound to its incoming pair, not a new manual test
  of these frozen downloads; see [Windows limits](../rpc/windows-release-scope.md).
- Production app signing/notarization, physical/OEM/hostile-network campaigns,
  independent-peer interoperability and professional cryptographic audit are
  not established by publication. The [canonical validation authority](../validation/README.md#current-status)
  retains the campaign statuses; [independent interop](https://github.com/p2pKit/P2pKit/issues/133)
  and [installed Windows validation](https://github.com/p2pKit/P2pKit/issues/462)
  remain separate requirements.

Earlier releases, tags, artifacts and failed results are immutable. This
bookkeeping retains `VERSION_NAME=0.8.0-rc5`, advances latest-published metadata,
selects no next snapshot and neither rebuilds nor changes the released bytes.
