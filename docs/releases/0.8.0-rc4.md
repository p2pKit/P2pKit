## Release changes and boundaries

The rc4 source integrates the productive Windows installed-provider/LAN path
and Android accepted-socket JNI repair, preserving fail-closed identity,
ownership and cleanup checks. JVM library bytecode remains JVM 17; the canonical
Windows native sample uses its pinned JDK 21 runtime without a JDK 17 fallback.
Android source builds require NDK `29.0.14206865`, with the API 24 floor retained.

The Maven release policy no longer requires a calendar-based token-rotation
deadline. Valid existing credentials may be retained; compromise, exposure,
revocation, provider requirements or a genuine operational need still require
action. Authentication/authorization, signing, protected approvals, integrity
and the separate evidence-retention policy remain enforced.

The Apple post-cancellation test now waits for an actual request and reply under
the existing receive bound before teardown, rather than equating local send
completion with remote receipt. Swift UI input recovery also respects late Start
acknowledgements before its single bounded retry. These fixture changes do not
relax production protocol/security checks or increase timeout budgets.
