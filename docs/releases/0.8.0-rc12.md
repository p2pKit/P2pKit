Fix [#543](https://github.com/p2pKit/P2pKit/issues/543): opt-in
`RpcClient.callWithAcceptance` waits for application validation and durable
persistence before permitting the exact result's Receipt. Immutable
`RpcResultAcceptance` exposes authenticated Host, request and procedure
association. Validation, persistence and cancellation failures before acceptance
send no Receipt or automatic acceptance retry. Queued Receipts retain deadline,
cancellation and physical-generation checks. Existing API signatures, automatic
Receipts, authentication, encryption, authorization, idempotency/recovery,
admission limits, defaults and the Apple baseline remain.

[API contract and usage](../rpc/durable-result-acceptance.md).
Persistence is application-owned: the callback must await its durable commit.
Receipt delivery remains best effort; a successful return does not prove remote
cache deletion. A crash or cancellation after commit cannot undo that commit or
recall an already-started Receipt. Use business idempotency keys for recovery.

Example coordinate: `io.github.apdelrahman1911:p2p-core:0.8.0-rc12`.
Keep Core/LAN/RPC modules on the same official version.

human reviews. Review found and fixed the blocking-callback monotonic-deadline
edge and nested acceptance-RPC exception association, with regression coverage.
The [final post-CI review](https://github.com/p2pKit/P2pKit/pull/544#issuecomment-6705199238)

tests, with zero failures/errors/skips. All four ABI views are additive; ABI
checks and strict Dokka passed. A real JVM journal test awaits
`FileChannel.force(true)` before Receipt; an actual closed-channel write failure
sends none. This is persistence-ordering evidence, not power-loss certification.

Initial local fixture failures are retained privately: coroutine debug recovery
copied a standard exception; a non-copyable fixture preserves exact identity
assertions. Real I/O originally used virtual time and missed its deadline; real
coroutine time fixes the fixture with the same timeout. A missing constructor
invocation caused one compile failure and was corrected. No assertion, deadline,
verification checksum, lock or platform gate was weakened. The original
[earlier-source PR run](https://github.com/p2pKit/P2pKit/actions/runs/42357648875)
was superseded and cancelled after the nested-exception fix, not credited.
