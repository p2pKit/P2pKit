# Documentation archive

These files preserve historical audits, trackers, decisions, runbooks, and
evidence. They are retained for traceability and release reproduction; they are
not current instructions or current product-readiness claims. Paths, versions,
status wording, and commands inside archived files reflect the repository state
when each record was written.

Use the [current documentation index](../README.md) for active guidance.

## Contents

- `remediation/2026-06/` — the June audit and original problem register.
- `remediation/2026-07/` — exhaustive review maps, findings, decisions, the
  authoritative completed remediation tracker, coverage plans, summaries, and
  the detailed 0.7 design specification. The formerly protected review
  workspace and its disposition are preserved under
  [`remediation/2026-07/review-campaign/`](remediation/2026-07/review-campaign/README.md)
  and [`LEGACY_MATERIAL_DISPOSITION.md`](remediation/2026-07/LEGACY_MATERIAL_DISPOSITION.md).
- `validation/legacy/` — superseded testing dashboards, stabilization/release
  runbooks, hardware checklists, and the pre-publication Maven guide.
- `evidence/v0.3/` — retained historical diagnostic evidence.

The archived `P2PKIT_REMEDIATION_TRACKER_2026-07.md` preserves all finding and
test-gap dispositions from the remediation program. Living external status is
maintained in [`../testing/validation-status.md`](../testing/validation-status.md),
and execution instructions are in
[`../validation/`](../validation/README.md).

Do not edit archived status to describe a later run. Add a dated release or
validation record under the current documentation structure instead.
