compatibility page distinguishes Kotlin ABI guarding from Java-source
callability and describes the mangled identity/DSL APIs versus ordinary
message/error accessors. The narrow Java `FileTransferFailed` mapping promise
is retained. Java applications are directed to application-owned Kotlin glue,
not reflection or compiler-internal workarounds.

bytecode exposes a public `P2pKitBuilder()` constructor, callable from Java.

Absence from a Kotlin-aware ABI dump is not JVM privacy. `Peer`/`PeerIdentity`
ordinary constructors are private; their public marker constructors are synthetic.

No facade, production code, ABI baseline, dependency, build or test source changed.
The fix is the issue's recommended documentation correction, not adoption of
end-to-end Java SDK support.
