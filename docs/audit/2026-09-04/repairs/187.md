The actual defect was Kotlin-aware JVM-family ABI tooling omitting already-emitted
public constants. The title's public Native-leak premise is refuted: real core
KLIBs for all three iOS targets contain `NOT_IN_V01` only inside private-companion
metadata, not exported ABI. Android/Desktop provisioning have no Native targets.
Signature baselines record names/descriptors, not constant values.

The new `PublicConstantAbi` helper reads supported owners and declared signatures
from committed baselines, then inspects actual producer classfiles using JDK
`javap` without loading or initializing application classes. It rejects new
unrecorded accessible constants, missing/ambiguous/wrong artifacts, diagnostics
and incomplete owner coverage. `VerifyPublicConstantAbiTask` integrates it with
ordinary JVM/Android ABI/module checks; root `checkPublicConstantAbiPolicy`
executes compiled positive/negative controls.

Only core JVM `NOT_IN_V01` and Desktop `DEFAULT_POLL_INTERVAL_MS` are explicit
omitted-baseline exceptions, required to remain **public** constants of their
recorded descriptors. Android's existing baseline entries remain unchanged.
All four legacy fields and values, ABI baselines, dependencies, publication
configuration and the legacy publication-symbol gate are preserved. The three
production Kotlin edits are comments only; no runtime or wire behavior changed.
Non-baselined Kotlin-internal JVM owners are not frozen as a new Java SDK contract.

Future breaking-version retirement remains a decision tracked in #187, requiring
coordinated source, Android baseline, JVM exceptions, publication gate and migration
guidance. #283's cleanup allegation remains refuted; #152's dynamic-caller
meta-assertion is a separate pending issue, not silently absorbed here.
