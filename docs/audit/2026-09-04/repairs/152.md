## Root cause and correction

The dynamic Android ABI graph probe **already ran** before this repair. Removing or adding `--static-only` to its
sole nested caller left all six exercised baseline toolchain/release-workflow/ABI-fixture policy invocations green.
This was removal resistance, not a currently absent check or a runtime/security defect.

Full CI and the release gate now each contain one explicit unflagged `scripts/check-android-abi-guard.sh` command.
The nested toolchain call is explicitly static-only, avoiding a second Gradle probe. Static policy requires these
call sites and rejects removal, downgrade, comments, duplication and ignored failure at either full caller, plus
missing/duplicate/hidden full nested calls. Fourteen new controls supplement seven retained cases.

The dynamic implementation, task registration, ABI baselines, dependencies, production code and
[#187's compiled-constant guards](187.md) are unchanged. These are source-policy tripwires, not general shell/YAML
control-flow analysis or adversarial tamper-proofness. The [local guide](../../../testing/local.md#android-abi-graph-verification)
distinguishes the real graph probe from static fixtures and actual ABI task execution.
