## Root cause and correction

`JvmLanNetworkWatcherTest.snapshotsRunOnTheInjectedIoContext` mixed `runTest` virtual `withTimeout(1_000)` with a real
single-thread executor. A correct snapshot dispatcher failed in 0.003 wall seconds when virtual time jumped to the
deadline. The test was unchanged from closed #159's regression commit; production `withContext(snapshotContext)` was
already correct and remains unchanged.

The external-worker wait now explicitly uses real `Dispatchers.Default` time, preserving the **one-second** bound and
injected-thread assertion. A FIFO latch gate deliberately queues the probe while virtual time advances 1,001 ms; the wait
must remain pending before releasing the gate. `finally` retires the watcher, releases the gate, closes the owned
executor and asserts bounded termination. No production/API/ABI/wire/security/resource-ownership implementation changed.
The finite real bound can still fail on an excessively stalled host; this removes clock mismatch, not all host failures.
