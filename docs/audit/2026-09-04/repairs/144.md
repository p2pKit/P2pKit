## Verified cause and correction

The complete issue, comments, timeline, related dispositions and merged PR #103's body, discussion, reviews and
commit history were read. Read-only live ruleset inspection confirmed active strict main checks plus the existing
administrator bypass/branch-creation exception. No bypass was exercised. PR #103's graph-reuse decision is superseded;
its exact merge/event identity, rename and whitespace protections remain.

Original `scripts/resolve-ci-scope.sh` treated a two-parent merge with first parent equal to the event-before commit
and a tree equal to its second parent as evidence of a successful PR check. Actual execution in four disposable
real Git repositories with no remotes showed source-changing, source-to-Markdown rename and empty merges wrongly
selecting lightweight scope. A genuine Markdown-only merge was a passing control. The old resolver suite passed
because its source-changing fixture explicitly expected the wrong result.

**Current impact is narrower than the historical issue.** Linux and Windows library suites already run
unconditionally; `complete-gate` requires their success. The removed shortcut skipped the macOS full path,
not every build/test. No mixed-file path-filter bypass or laundering onto a different Git tree was demonstrated.

The correction removes reuse entirely rather than introducing a check-run API/permissions:

- Every valid main push classifies the complete event-before-to-checked-out-HEAD delta, including exact-tree merges.
- Nonempty Markdown-only changes remain lightweight. Source/configuration paths, renames and empty deltas request
  full checks. Missing/non-ancestor push bases retain all-tree fallback; invalid event identities fail closed.
- Manual dispatch and a weekly Monday **04:17 UTC** schedule request full/all-tree scope.
- Scheduled runs have a distinct concurrency group and do not cancel running schedules. Ordinary per-ref
  push/manual supersession remains. Required check names, permissions, action pins and cross-host guards are unchanged.
- Contributor/testing guidance states what lightweight proves and the unchanged owner-controlled ruleset duties.
- The new workflow-policy regression runs in lightweight CI, the full release-workflow caller and the release gate.
