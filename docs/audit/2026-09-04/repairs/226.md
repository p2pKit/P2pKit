## Root cause and correction

The unchanged baseline curator used a random, private `/tmp` workspace despite a usable operator-selected `TMPDIR`.
An offline real-entry-point fixture confirmed placement and the original successful EXIT cleanup before any curator
downloads/GPG. This was not a predictable-path vulnerability or demonstrated `noexec` failure.

Artifact, signature and metadata storage now follows `${TMPDIR:-/tmp}` without silent fallback. A separate small GPG home
uses `${P2PKIT_GPG_TMPDIR:-/tmp}`; both parents must exist. Its complete physical longest standard agent-socket pathname
is bounded to **102 bytes**, before downloads/GPG, using the existing byte locale. Actual macOS GPG 2.5.20 and libassuan
3.0.2 establish this boundary: the kernel accepts 103 bytes, but libassuan's strict guard reserves two of the 104 bytes.
This does not use a guessed prefix-length threshold or move large artifacts back to `/tmp`.

Cleanup is installed before allocations. Errors and handled HUP/INT/TERM signals clean partial or complete setup;
home-scoped `gpgconf --kill all` stops only the review keyring's workers before deleting their socket directory. Failed
shutdown makes an otherwise successful invocation fail and preserves the keyring with a shell-quoted retry command;
artifact cleanup still runs. SIGKILL/power loss cannot run shell cleanup. Documentation explains roots, prerequisites,
the physical byte limit and explicit retry. Equivalent Python-prerequisite condition rewrites remove inherited SC2015
warnings without changing admission semantics.

No production/library/sample API/ABI, platform source, dependencies, lock/verification metadata, workflow or protected
instruction change. Prior signature/issuer, checksum, attestation, unsigned-plugin, signed-variant and bounded-parser
contracts remain intact. The unchanged ambient packet/key-inspection concern is an [unconfirmed follow-up](../followups.md#dependency-curator-ambient-gpg-packet-and-key-inspection),
not a demonstrated disclosure or part of this approval.
