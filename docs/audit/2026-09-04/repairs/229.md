## Root cause and correction

Actual locked JmDNS 3.6.3 normalizes malformed UTF-8 before **both** property APIs. Switching only to `getPropertyBytes`
would not fix the defect. Original `ServiceInfo.textBytes` now feeds a common bounded raw-RDATA parser; JVM/Android
admission, remaining diagnostic PID reads and refresh self-filtering use it. Input is capped at 65,535 bytes before
processing; unsigned entry lengths/truncation and complete fixed ASCII keys are checked. Every consumed occurrence
is strictly decoded. Unknown values are not decoded/retained. Malformed known duplicates reject the entire record;
valid duplicates keep the last value. Empty/boolean values remain empty; valid strings are not trimmed/NUL-stripped.

Correctly encoded literal U+FFFD is valid and remains accepted; semantic controls, identity/profile checks and
diagnostic sanitization stay intact. #332's current JVM/Android invalid-record withdrawal remains active. No public
API/ABI, dependency, wire schema, authentication, session or file-durability change. This is not an authentication bypass.

Apple production code is unchanged. Approval is for canonical known-key **value** decoding, not universal arbitrary
RDATA/platform/lifecycle parity: [#356](https://github.com/p2pKit/P2pKit/issues/356) separately tracks pre-existing Apple
C-string key aliasing. The Apple invalid-re-resolution [follow-up](../followups.md#apple-same-generation-invalid-re-resolution)
is unconfirmed. Changelog/checklist reserve admission tightening for **0.8.0+**; the current snapshot label authorizes
no earlier release or retroactive RC3 change.
