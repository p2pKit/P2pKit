## Confirmed cause and correction

`startSession("test", ...)` normalizes the recorder's test ID to `TEST`. The real exporter uses the captured
summary fields, but the old `DiagnosticApi24Probe.failedExport` created its nonempty-directory obstacle at the
raw lowercase basename. On the reproduced case-sensitive Linux filesystem, export succeeded at the different
uppercase path. The resulting `IllegalStateException` came from the fixture's failed `IOException` predicate,
not an exporter exception. Message-only instrumentation demonstrated that distinction and was restored exactly.

The probe now derives the obstacle from one captured summary, retaining the deliberately lowercase session input.
An independent exact `String` basename guard pins the normalized uppercase context before directory creation,
so case-insensitive `File` equality cannot hide reintroducing the mistake. The caller runs the failure scenario
sequentially in separate directories/loaders for the default missing-API26 model and synthetic SDK24/SDK25.

The real exporter/older-API replacement path, `IOException`, unrelated-content preservation, absence of a success
event and owned-staging cleanup checks remain. The repair also requires exactly one canonical failure event with
`evidence_export_failed`, failure outcome and error severity. The lowercase code follows existing `stableName`
normalization; the first incorrect uppercase oracle was corrected, not relaxed. Production source, classloader
isolation, API, dependencies, minimum SDK, existing skips and timeouts are unchanged. Actual Android, CLI,
Desktop UI and evidence-generator callers pass the recorder to the exporter; they do not build this obstacle.
