## Confirmed cause and correction

The original estimator encoded Text and each metadata key/value solely to count temporary UTF-8 bytes. It ran
before the count guard and charged wire lengths without container allowances. The collection was already bounded:
this is bounded allocation/retention amplification after session admission. The default v2 path requires authenticated/
authorized admission; this is not a pre-admission LAN finding. Explicit plaintext mode also reaches this accounting.
`Binary.payloadSizeBytes` was already the actual private defensive-copy length; its alleged under-reporting was refuted.

Admission now checks the unchanged 64-message cap first under the existing accounting mutex, then applies:

- 512 bytes/message;
- two bytes per Text UTF-16 code unit, or the actual private Binary payload length;
- 256 bytes/metadata pair, plus two bytes per key/value UTF-16 code unit.

Arithmetic widens before addition/multiplication. The unchanged 8 MiB charge limit includes in-flight delivery.
Admission records one charge; emission, failed-channel-send rollback and terminal drain release that same ownership.
Rearm, cancellation, underflow assertions, secure authorization, protocol limits and Binary defensive copies remain.
No new public API, ABI baseline, dependency, production test hook, wire format or protected instruction changed.

Work is independent of payload/string length and O(metadata entries), bounded at 64 for decoded input. No content
encoding/copy is performed by measurement, but a small iterator can allocate. The fixed allowances are conservative
**policy estimates**, not measured universal object-layout upper bounds or whole-session/process heap guarantees.
This explicitly refines the old issue's literal zero-allocation/O(1)/true-heap acceptance wording; no heap profile
or Native allocation measurement was performed.

**Compatibility:** this is tighter admission, reserved for **0.8.0+**, not a 0.7 release. With no metadata/backlog,
4,194,048 ASCII code units exactly consume 8 MiB; one more is refused. A legal maximum 4 MiB ASCII Text costs
8 MiB + 512 bytes and fails the receiving session even into an empty queue. Neither cap is raised. The KDoc,
[limits reference](../../../reference/limits.md), changelog and release checklist disclose this boundary without
changing a version/tag or authorizing publication.
