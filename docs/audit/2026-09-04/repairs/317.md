The original unused delegated local collected the flow without reading its Compose
State, so incoming events did not register the intended invalidation dependency.
The actual screen now calls `rememberDiagnosticEvents`, which reads the revision
as a `remember` key and also keys the filter and source. Event-only changes update
the list and the surrounding summary; equal-counter source replacements cannot
reuse another recorder's snapshot.

Because clearing emits no diagnostic event, `AndroidDiagnosticHarness` now invokes
its retained invalidation callback after successful persisted/in-memory clearing
and correlation reset. Failed clears preserve memory and report failure. Pause
remains a display snapshot, not a recorder pause. Composition disposal cancels its
collector; no new polling loop, unbounded queue or per-event coroutine was added.

Library APIs, the ViewModel, Desktop/Apple implementations and the wire protocol
are unchanged. Closed #294's unmeasured performance allegation and #315's polling
decision remain separate; #316's unused APIs are not claimed fixed. #352's selective
clearing and explicit non-crash-atomic storage limitations are preserved.
