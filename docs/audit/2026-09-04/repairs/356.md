## Root cause and correction

Apple's C-string TXT-key traversal could interpret `name\0suffix` as the canonical `name` key. Native raw-buffer
representations also failed to enumerate valid canonical fields after an unknown alias. `IosBonjour.kt:77-87` now
uses `nw_txt_record_access_bytes` for both representations, copying only within the native callback lifetime.
The common accessor overload (`LanTxtRecord.kt:11-17`) bounds the original unsigned length to **65,535 before
narrowing/copying**. Zero bytes do not dereference storage; missing or short/long nonempty copies reject.
Failed access, malformed framing or malformed consumed values cannot produce a successful partial map.

The unchanged byte-array parser matches complete canonical keys and strictly decodes every consumed occurrence.
Unknown NUL aliases cannot supply or overwrite fields. Valid Unicode/literal U+FFFD, empty/boolean values, duplicate
ordering and owned results remain intact. Existing JVM/Android behavior, Apple admission/removal lifecycle gates,
authentication, namespaces, wire schema, public API/ABI and dependencies are unchanged. This is not an authentication
bypass or a cache-lifecycle correction. Changelog/checklist reserve admission changes for **0.8.0+**, despite the
unchanged snapshot label; published RC3 artifacts/tags are untouched.
