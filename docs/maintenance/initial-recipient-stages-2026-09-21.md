## Why two stages

The previous [joint matcher](../../scripts/hosted_initial_recipient_exception.py)
required a first PR and ordinary run IDs even for bootstrap. Opening that PR is
not metadata-only: current JVM jobs can start Gradle before FULL's literal HOLD,
including their `always()` cleanup. A failed HOLD is not a suspended attempt.
Later separately authorized HOLD changes would also change the reviewed head.
The old source-only approval remains valid for that old supplied-record scope;
it is not an executable allocation path or a fallback for these stages.

The independent design recommendation at `61e46eaef5221f6a0ca54be1a2a9b1f8d9223343`
(tree `cfde1fd8cea57d738c5c6ca5968461767b0d272a`) was
