# Fixed installed Windows UI control

**Implementation under qualification. NOT_READY; no UI result is implied by this document.**

`scripts/run-windows-installed-admission.py --operation ui-host-cycle` uses the existing
original-process/job supervisor to start the canonical installed `MainKt` application with
the single exact `--rpc-windows-disposable-ui-host-cycle` argument. Account, interactive
session, private fixed-NTFS profile context, trusted startup, installed bytes and outer
supervisor admission remain prerequisites. The argument supplies no loader authority.

Use only the approved disposable application's existing synthetic profile, created by
the maintained profile control. The first step is its normal productive `profile-reopen`
control: an absent, unrelated or ambiguous fixture refuses without reset. Raw profile
and UI evidence stays private. The native smoke needs its own fresh disposable context.

The control enters the ordinary Compose application body and retains its actual window.
It finds exactly one enabled/showing RPC accessibility action in that window, then drives
the real embedded panel's Host, passphrase dialog, Stop, Host and Back controls. It observes
actual rendered Ready/Running/Stopped states and unchanged full fingerprint across Stop.
It never constructs a substitute panel, injects a runtime/provider, invokes role methods
directly, selects a peer, grants trust, changes network policy or resets the identity.
Ambiguous/oversized accessibility trees, missing controls, failed unlock and unresponsive
events refuse. Posted work checks its deadline again before entering an action.

The UI worker has a subordinate ten-second deadline. The canonical command's existing
15-second work/5-second cleanup limits and original 30000ms outer deadline are unchanged.
The worker requests the real window-close event on both success and failure. It cannot
declare cleanup successful or force a zero exit. Its bounded JSON describes provisional
UI observations and `terminalClose=REQUESTED`; acceptance also requires the original
supervisor's timely exit0, closed captures, known cleanup and retired process witnesses.
Failure output includes a fixed stage and closed-vocabulary rendered-state observations, never
exception text, passphrases or fingerprints. State numbers 1–6 mean Idle, Stopped, Host Starting,
Host Ready, Host Stopping and Host Failed; 0 means no recognized rendered state. Boolean fields
report original-window activity, the generic profile-refusal message and Host/Stop enablement.
The optional rendered failure category distinguishes discovery scope, missing/ambiguous LAN,
cancellation, an RPC failure and other failure without copying any arbitrary UI text.
Startup errors remain classified after the original owner retires to Stopped; retirement
does not turn a failed start into a successful lifecycle result.
These observations identify a stalled stage; they do not substitute for native failure evidence.
Failure output also records elapsed monotonic milliseconds at each fixed stage and whether the
original ten-second deadline expired. It contains no exception message, identity or user input;
the timing observation neither extends a budget nor turns partial UI progress into a pass.
The controller publishes its original worker before start, invalidates queued actions during
terminal concealment and is joined by the original application's retirement worker. Unknown
retirement fails within the unchanged terminal/outer budgets.

The normal empty-argument application path never creates this controller. MainKt, window
ownership, section reservations, terminal watchdog, JNI retention and packaging remain
the production paths. CLI-selection, cross-operation receipt and malformed-output controls
must pass before actual execution; affected harmless Windows supervisor controls must also
pass. Record source/tree, MSI/runtime/installed-byte bindings and each original receipt.

One successful invocation is a narrow installed Host lifecycle observation. It does not
qualify two-device requests, peer approval/revocation, hostile paths/tokens, fault recovery,
all native resource retirement, or the required 20-cycle campaign. Count only actual
successful invocations; preserve every failed or timed-out attempt separately.
