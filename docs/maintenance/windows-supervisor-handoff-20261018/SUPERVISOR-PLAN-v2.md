# Reviewed mechanism proposal v2: fixed installed diagnostic outer supervisor

Supersedes plan v1 mechanism choice only. No implementation or execution yet.

## Ownership and interface
Implement only `scripts/run-windows-installed-diagnostic.py` and `scripts/tests/run-windows-installed-diagnostic-test.py` in the reserved worktree. Root owns the external PowerShell observer and usage notes. Public parameters: `--start-counter`, `--counter-frequency`, `--expected-source` (the actual installed application commit, currently 33d), `--private-parent` (existing separately admitted restricted owned directory). No caller command, launcher path, variable timeout, account override or product flags.

PowerShell starts `[Diagnostics.Stopwatch]::GetTimestamp()` **before creating Python**, records its actual frequency, and passes both. Python binds original Win32 QueryPerformanceCounter/QueryPerformanceFrequency, requires exact frequency agreement, rejects future/exhausted/malformed starts and computes the one fixed end as start + frequency*30. No assumption that Python time.monotonic has the same epoch. It observes remaining time using QPC throughout, including watchdog wakeup and finalization. The PowerShell observer independently observes actual Python process exit and total elapsed <=30,000ms; no receipt/console line alone passes.

The helper starts a daemon hard-watchdog thread in the outer observer before scope creation, KnownFolder lookup, worker creation or other native preparation. This separate outer **process** supervises the E worker. Keep its watchdog armed through `os._exit`: no disarm/join success claim. At the cutoff the watchdog terminates its own outer process with fixed nonzero status, without waiting for logging/locks/cleanup; closing the sole noninherited outer kill-on-close Job requests termination of its nested members. Timeout/kill never proves cleanup. Source trusts ordinary CPython/GIL scheduling and OS operation: this is not a hardware hard-real-time or arbitrary stalled-kernel/interpreter guarantee. Any late external observation is nonpassing.

## Fixed invocation and unchanged canonical executor
After watchdog admission, resolve ProgramFiles from fixed OS shell32 SHGetFolderPathW CSIDL_PROGRAM_FILES=0x26/current on native Windows x64, and derive only `P2pKit Sample\P2pKit Sample.exe`. No ProgramFiles environment lookup/fallback. The actual executable receives exactly `--rpc-windows-installed-admission`. Fixed expected diagnostic JSON shape is the existing MainKt `{source,admission}` with source equal to `--expected-source`, admission REGISTERED/repeat REUSED/storage and network NOT_ENTERED/publicProvider DISABLED. This is output checking, not load authority.

The outer controller owns an original canonical `audit_processes.WindowsScope`, launches the same fixed helper in private internal worker mode with suspended atomic job assignment, and retains the original worker process handle plus bounded original capture owners. Its worker invokes unchanged `ci_evidence.run_command` once, which creates the nested original WindowsScope for the installed launcher. Job assignment/no-breakaway must encompass jpackage's descendants; no reconstructed PID, process-name kill, shell execution or unmanaged subprocess launch.

Worker work <=15s and cleanup <=5s; compute both from the original QPC remaining budget leaving an explicit outer reserve, not from a renewed 30s clock. E's existing relative cleanup handling cannot extend the outer cutoff. The outer observer also clips its graceful/kill/drain/capture/record work to the original end. Deadline checks after every potentially blocking return reject late success. Preserve the unchanged E result even when nonpassing; no typed failure is converted to retryable unavailability.

Require actual worker exit0, complete valid finite worker record, exact expected app output with empty stderr, E PASS/exit0/no timeout/known cleanup/closed captures, quiet original outer Job, no discovery/retirement uncertainty, both outer capture closures and timely record finalization. Require external observed outer exit0 within 30s too. Missing/late/duplicate/malformed output, excess output, cancellation, uncertain close or lingering descendants are nonpassing. No retries or fixture reset.

## Record and privacy
Separate `supervisorSource` (helper commit/tree/files) from `appSource` (expected and observed installed commit33d). Do not rebuild the MSI or imply helper changes alter installed bytes. Packet author supplies actual package provenance and source bindings, not invented pins. Create one fresh private child below the previously admitted restricted parent; hold/recheck original parent custody where the maintained private-file adapter admits it, never relax its policy. Only bounded logs and finite result fields, no exception text/paths/SIDs/credentials in public output. The private child basename is an output locator, not authority. The final private receipt and fixed public summary are accepted only together with the independent outer exit observation.

User/token/disposability/installed bytes/root ACL/trusted-startup approval remain caller preflight responsibilities. This helper cannot authorize the installed test or complete provider and does not change native admission policy.
